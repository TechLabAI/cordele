# 04 — Frontend Architecture Direction — COMP (Composição)

## 1. Stack

- Angular **21**, Nx **22.x**, TypeScript **strict**.
- RxJS 7.8 **+ Signals** (Signals are the default state primitive and drive the live layout preview;
  RxJS only where streams are intrinsic — e.g. debouncing/cancelling a cover upload or a hydrate).
- Jest for unit tests, **Playwright** for e2e (`apps/comp-e2e`).
- Custom dark design system via CSS tokens (`theme.css`) + Tailwind utilities; no SCSS token layer.
  The preview canvas renders on a simulated light "paper" surface (it mimics the page, not the app).
- Package scope **`@cordele`**; module skeleton generated by the local Nx plugin
  `@cordele/internal:module`.

## 2. App Boundary

COMP is registered in the Shell (`cordele-web`) via `COMP_MODULE_DESCRIPTOR`. The lazy entry is
`comp.module.ts`, living in `libs/comp/shell-entry` with importPath `@cordele/comp` (ADR-006).
`apps/comp` is a thin host whose `app.routes.ts` only does
`loadChildren: () => import('@cordele/comp').then(m => m.CompModule)`, serving as build/serve target
and e2e base. COMP is **not** a landing module — it is entered from IMP (on confirm) or from PROJ
("Abrir" / "Ajustar metadados / layout") and only for a project in `em_composicao`.

## 5. Routing Strategy

- Shell → `@cordele/comp` via `loadChildren`; COMP is **not** a default child (entered on handoff).
- Sub-routes via `loadComponent`: `/config` → `feature-metadata`, `/editor-de-layout-preview` →
  `feature-layout`. Specs may nest both behind a project id (e.g.
  `/projetos/:projetoId/config`, `/projetos/:projetoId/layout`) so the aggregates are always scoped.
- Guards: `canActivate: [authGuard, empresaGuard, accessGuard('comp.edit'), compStatusGuard]`, where
  `compStatusGuard` admits only `em_composicao` and redirects otherwise (to PROJ).
- **Intra-COMP flow order** (`/config` → `/editor-de-layout-preview`) is enforced by the step bar +
  the `canAdvance` gate; deep-linking straight to layout is allowed but the layout screen still
  requires valid metadata (Specs decides whether it redirects to `/config` or shows a soft warning).

## 6. State Strategy

- **Signals-first, no NgRx.** Each facade holds private `signal<T>` and exposes `.asReadonly()`:
  - `MetadataFacade` — `MetadataFormVM` + `status`; `computed()` for `canAdvance` and cover state.
  - `LayoutFacade` — `LayoutVM` + `PreviewVM` + `status`; the live preview binds directly to the
    layout signals so a slider change repaints with **no server round-trip** (the canonical
    signals-first case for this module).
- `computed()` for derived values (`totalPaginas`, `paginaConteudo`, `canAdvance`).
- No manual `BehaviorSubject`; RxJS is confined to the edges (cover upload with debounce/cancel,
  hydrate requests) and converted to signals (`toSignal`) at the facade boundary.
- **No optimistic writes.** Persistence of `Metadados`/`ConfiguracaoLayout` is **pessimistic on
  advance/export**: the facade awaits the `200`/`204` before navigating; live edits are local until
  then, so there is nothing to roll back (ADR-COMP-001).

## 7. Module Contract Strategy (`comp.contract.ts`)

| Field | Value (draft) |
|---|---|
| `MODULE_KEY` | `'comp'` |
| menu label | `Composição` |
| icon | tune / settings glyph (`tune`) |
| permissions | `comp.view`, `comp.edit` |
| feature flags | `comp.livePreview` (defaultState: on), `comp.structuralEdits` (defaultState: **off** — R7, prototype toolbar deferred) |
| routes anchor | `COMP_ROUTES` (`/config`, `/editor-de-layout-preview`) |
| landing | not a landing module (`isHome: false`); entered from IMP/PROJ on `em_composicao` |
| entry point | `COMP_MODULE_DESCRIPTOR` (consumed by `module-descriptors.ts` in Shell) |
