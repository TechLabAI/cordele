# Backend Architecture -- Cordelê

Entry point for everything the backend of Cordelê decides, prescribes or plans.
Read this page first; every other document under `docs/architecture/backend/` is reachable from here.

## Stack in use

| Tier | Value |
|---|---|
| Base language | `node` |
| Framework | `nestjs` |
| Build tool | `pnpm` |
| Persistence | `prisma` |

## What lives where

| Directory | Content | Written by |
|---|---|---|
| `standards/` | Prescriptive rules: layering, conventions, testing, EARS notation. Normative. | architecture team |
| `adr/` | Architecture Decision Records: one decision, its context and its consequences. | `/be-architect-vision` + humans |
| `plans/` | `architecture-master-plan.md` plus one `plan-<MODULE>.md` per module. | `/be-architect-backlog` |
| `issues/` | Atomic, implementable issues derived from the specs. | `/be-architect-backlog` |
| `services/` | One directory per backend service: service spec, docs 01..06, contracts, local ADRs. | `/be-architect-vision` and `/be-architect-specs` |

## How to navigate

1. **Starting a module** -- read `plans/architecture-master-plan.md` for the module's status, then
   `services/<service>/` for its vision and contracts.
2. **Writing code** -- the binding rules are in `standards/`. A rule stated there wins over an
   example found in an existing service.
3. **Changing a rule** -- rules are not edited in place: raise an ADR in `adr/`, and only then
   update the standard it supersedes.
4. **Looking for the why** -- `adr/README.md` indexes every decision on record.

## Conventions

- Documents are written in en-US and are versioned with the code they describe.
- Cross-references use the `[[../path/document]]` wiki form, without the `.md` extension.
- A document generated by a pipeline command carries its provenance in the header; edit the
  source of truth (specs, context) rather than the generated page.
