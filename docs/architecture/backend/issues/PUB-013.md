# PUB-013 -- OAuth2 guard + EmpresaContext middleware + scopes pub:read / pub:write

**Status:** INTACT -- gerado 2026-08-25
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/5 itens

## Contexto

Implementar o guard OAuth2 (JWT Bearer) para o `PubController`, o middleware `EmpresaContext`
(AsyncLocalStorage) que resolve o tenant exclusivamente do claim do JWT, e os decorators de scope
`pub:read`/`pub:write`. Replicar padrão de COMP/PROJ (shared ADR-003, RULE-07). O `EmpresaContext`
deve estar disponível no job assíncrono `PublicationBuildJob` para que queries Prisma escolham o schema
correto durante o build.

## Spec de referencia
- SPEC-06 (security — auth JWT, scopes, EmpresaContext, confidencialidade do artefato)
- `contracts/api-contract.md` §2 (authentication, authorization, tenancy)

## Escopo

Files to create (relative to monolith root `backend/`):

- [ ] `src/modules/pub/auth/jwt-auth.guard.ts` — `CanActivate` que valida Bearer JWT via `OAUTH2_JWK_SET_URI`; retorna `401` sem token, `403` com scope insuficiente; extrai `empresaSlug` do claim e popula `EmpresaContext`
- [ ] `src/modules/pub/auth/empresa-context.middleware.ts` — NestJS middleware que resolve `empresa` do JWT claim e chama `EmpresaContext.run(slug, next)` via `AsyncLocalStorage`; cross-tenant `projetoId`/`publicacaoId` retorna `404` (nunca revela existência)
- [ ] `src/modules/pub/auth/pub-scope.decorator.ts` — decorator `@PubScope('pub:read' | 'pub:write')` aplicado por rota; consumido pelo guard
- [ ] `src/modules/pub/auth/jwt-auth.guard.spec.ts` — unit tests: token válido com `pub:write` → autorizado; token válido sem scope → 403; token ausente → 401; `empresaSlug` corretamente extraído e injetado no `EmpresaContext`
- [ ] `src/modules/pub/auth/empresa-context.ts` — (se não já shared) `AsyncLocalStorage`-backed `EmpresaContext` com `getSlug()`, `run(slug, fn)` — reutilizar implementação de COMP se já existir em shared
