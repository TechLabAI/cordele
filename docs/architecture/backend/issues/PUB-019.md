## Contexto

Implementar os step definitions BDD que o `be-bdd-generator.py` **não** consegue gerar
automaticamente (identificados em M3 como itens de step definition manual):

1. `project {string} has the following publicacoes:` com DataTable (`status`, `epubcheckStatus`,
   `sequencia`) — seed de múltiplas `Publicacao` com estados explícitos; DataTable é o padrão
   canônico para fixtures multi-linha (evita parentheses no step text que causam parse error
   jest-cucumber).
2. `epubcheck cannot execute due to a missing JRE or JAR path` — configura o fake do
   `EpubValidationPort` para simular ausência de JRE/JAR.
3. Cenário complementar `emAndamento=1` em `publication-build-async-polling.feature`: projeto com
   build em `gerando` → `stats.emAndamento=1`; ausente no feature file atual (gap M3).
