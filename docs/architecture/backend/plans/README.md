# Plans -- Backend

Two levels of planning for the backend of Cordelê, both generated, never
hand-authored.

## `architecture-master-plan.md`

The project-wide board: one row per module, one column per architecture phase (Vision, Specs,
Backlog, Scaffold). It answers "where is this module" and nothing else.

- It is written and updated by `scripts/master-plan.py` -- **never** by hand and never regenerated
  from scratch by an agent (D-516). Use `master-plan.py ensure` (a no-op when the file is present)
  and `master-plan.py set-status` to move a cell.
- The copy under the client governance hub and the copy in this repository must both be updated
  after every phase; they are not synchronised automatically.

## `plan-<MODULE>.md`

One file per module, written by `/be-architect-backlog <MODULE>`. It is the ordered reading of the
issues in `../issues/`: priorities, dependencies between them, and the slice of the module each
priority delivers. `/be-validator` reads this file to decide what runs next, so an edit here changes
what the execution layer does.

| Artifact | Generated by | Consumed by |
|---|---|---|
| `architecture-master-plan.md` | `scripts/master-plan.py` | humans, `/next-phase`, the autopilots |
| `plan-<MODULE>.md` | `/be-architect-backlog` | `/be-validator`, `/be-planner`, `/be-implement` |
